今回の書籍制作については、当初、従来どおりAdobe InDesignを使用して組版を行うことを想定しお見積りを提出しました。

しかし、今後一冊だけではなく、二冊、三冊と継続して出版していくことを考えると、毎回同じようにWord原稿を受け取り、InDesignで一から組版する方法が、岡林さんにとって本当に最適なのだろうかと思うようになりました。

そこで、今後の出版活動を見据え、**MarkdownとCSSを利用した、シンプルな出版制作環境を最初に構築すること**をご提案します。

## **1．今回ご提案したいこと**

翻訳原稿をWordなどネイティブ・アプリケーション（ソフトウェア）ではなく、Markdownというシンプルなプレーン・テキスト形式で作成し、その原稿をあらかじめ設計した書籍用テンプレートに流し込むことで、縦組の書籍PDFを生成できる環境を構築します。

イメージとしては、

**翻訳原稿を書く  
→ 書籍用の形式に整える  
→ PDFを生成する**

という流れです。

組版には、HTML/CSSによる書籍組版に特化したオープンソース技術「Vivliostyle」を中心に使用することを想定しています。

原稿そのものはプレーン・テキスト形式で保存しますので、特定のネイティブ・アプリケーションだけに原稿資産が閉じ込められることもありません。

## **2．なぜMarkdownなのか**

Markdownは、文章を書くための非常に簡潔な記述方法です。

例えば、

- 章
- 見出し
- 本文
- 引用
- 注釈
- ルビ
- 強調

などについて、最低限のルールを決めて原稿を作ります。

一度そのルールを決めてしまえば、執筆者・翻訳者は基本的に**文章を書くことに集中できます。**

お二人はApple社製のPCをお使いのようですので、私自身と同じ環境で構築・説明・サポートができることも大きな利点です。

## **3．目指す制作フロー**

従来は、

**Word原稿  
→ DTP作業  
→ InDesign組版  
→ 修正  
→ PDF**

という工程になります。

今回構築する環境では、

**Markdown原稿
→ 書籍用CSSによる組版処理
→ PDF生成**

という流れを目指します。

もちろん、実際の出版物には人間による確認と調整が必要です。

特に日本語の縦組書籍では、

- 文字組み
- 禁則処理
- ルビ
- 行間・字間
- 見出し
- 柱
- ノンブル
- 改ページ
- 引用
- 注釈
- 欧文との混植
- 図版
- 奥付

など、単に文字を流し込めば終わりというものではありません。

この部分については、私がこれまで約30年間携わってきた印刷・DTP制作の経験を生かしながら、**「自動化できる部分」と「人が判断すべき部分」を整理した仕組み**にしたいと考えています。

## **5．大切にしたいこと**

今回の目的は、単に「InDesignを使わずに本を作る」ことではありません。

一冊目を作るためだけの仕組みではなく、今後、**二冊目、三冊目、そしてその先の出版にも利用できる制作環境**を作ることを目標にしています。

書籍が変わるたびに一からすべてを作り直すのではなく、原稿の基本構造と組版の仕組みを共有し、少しずつ改善しながら育てていく。

そのような方法であれば、小規模な出版であっても、制作コストを抑えながら継続して本を出していく可能性が広がるのではないかと考えています。

一方で、現在はWeb制作にも携わっており、HTML、CSSなどを使った制作も行っています。

今回の方法は、**印刷・DTPの経験と、Web技術のちょうど中間にある仕事**だと感じています。

私自身にとっても、新しい技術を使いながら、これまで長く携わってきた印刷・出版の経験を今後も生かしていける仕事です。
