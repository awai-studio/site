# JavaScript開発環境・依存パッケージ更新方針

最終更新：2026年8月13日

## 1. この文書の目的

Awai Studio、上田プロジェクト、および今後作成する共通雛形において、Node.js、Next.js、React、Supabaseなどのバージョン管理方法を統一する。

「常に最新版へ更新する」のではなく、開発中の安定性、安全性、再現性を優先する。

---

## 2. 基本方針

- 制作途中では、原則としてメジャーバージョンを変更しない。
- セキュリティ修正を含む更新は、開発の区切りで確認する。
- 実験版、ベータ版、canary版は、本番案件では使用しない。
- 更新前の状態をGitで保存する。
- 複数の主要パッケージを理由なく一度に更新しない。
- 更新後は、ビルドと主要機能の動作確認を必ず行う。
- 動作している既存案件へ、理由のない変更を加えない。
- 更新の理由、変更内容、確認結果を記録する。

---

## 3. 現在のAwai Studioの環境

```text
Node.js：22.23.2
Next.js：16.3.0
React：19.2系
```

Next.js 16とReact 19.2は、正式に対応している組み合わせである。

Node.js 22はLTSとしてサポートされているため、Awai Studioの制作途中でNode.js 24などへ変更しない。

まず現在の環境で、ブログ、レビュー、GA4、GTMまで完成させる。

---

## 4. 制作途中の更新ルール

制作途中では、次の場合に限って更新を検討する。

- 使用中のバージョンに重大な脆弱性が見つかった。
- 利用するライブラリが、現在のバージョンをサポートしていない。
- 現在のバージョンでは解決できない不具合がある。
- 本番環境が現在のバージョンをサポートしなくなった。
- 更新しなければ開発を継続できない明確な理由がある。

単に「新しいバージョンが出た」という理由だけでは、制作途中に更新しない。

---

## 5. 更新前に行うこと

最初に現在の変更状況を確認する。

```bash
git status
```

未保存の変更がある場合は、内容を確認してコミットする。

```bash
git add .
git commit -m "save current state before dependency update"
```

必要に応じて、更新作業専用のブランチを作る。

```bash
git switch -c maintenance/update-dependencies
```

更新前に現在のバージョンを確認する。

```bash
node -v
npm -v
npm list --depth=0
```

---

## 6. 更新後に必ず行う確認

### 6.1 脆弱性の確認

```bash
npm audit
```

### 6.2 本番ビルドの確認

```bash
npm run build
```

### 6.3 ブラウザでの確認

最低限、次の機能を実際に操作する。

- トップページが表示される。
- グローバルメニューが動く。
- スマホメニューが動く。
- モーダルが開閉できる。
- 管理画面へログインできる。
- 管理画面からログアウトできる。
- フォームを送信できる。
- ブログ記事を作成・編集・公開できる。
- ブログ画像をアップロードできる。
- 一般公開ブログの一覧と記事本文が表示される。
- 予約やレビューなど、既存機能が壊れていない。

ビルド成功だけで、更新作業を完了したことにしない。

## 7. package.jsonのバージョン指定

今後作る共通雛形では、主要パッケージのバージョンを原則として固定する。

```json
{
  "dependencies": {
    "next": "16.3.0",
    "react": "19.2.1",
    "react-dom": "19.2.1"
  }
}
```

次のような `^`付きの指定は、インストールする時期によって実際に入るバージョンが変わる可能性がある。

```json
{
  "dependencies": {
    "next": "^16.3.0"
  }
}
```

案件ごとの環境を再現しやすくするため、共通雛形では完全なバージョン番号を記録する。

`package-lock.json`も必ずGitで管理する。

---

## 8. 将来作る共通雛形の方針

Awai Studioと上田プロジェクトが一段落した時点で、共通雛形を作成する。

共通雛形を作る時点で、次の安定版を選択する。

```text
Node.js：その時点のLTS
Next.js：その時点の最新安定版
React：採用するNext.jsが正式対応する安定版
Supabase：採用環境で動作確認できた安定版
```

共通雛形では、次のものを記録する。

- 採用したバージョン
- 採用理由
- 対応するNode.jsのバージョン
- インストール手順
- 環境変数
- ディレクトリ構成
- 認証方法
- RLSの設定
- ビルド方法
- 動作確認項目
- 更新手順

---

## 9. 既存案件への反映方法

共通雛形を更新しても、Awai Studioや上田プロジェクトへ自動的に変更を反映しない。

各案件で次の順番を守る。

```text
更新内容を確認する
↓
その案件に必要か判断する
↓
専用ブランチで更新する
↓
ビルドする
↓
主要機能を操作する
↓
問題がなければmainへ反映する
```

雛形と既存案件は、同じ思想と構成を共有する。ただし、既存案件で動いているコードを理由なく書き換えない。

---

## 10. セキュリティ更新の扱い

重大な脆弱性がある場合は、通常の更新時期を待たずに対応する。

ただし、次のようなコマンドを内容の確認なしに実行しない。

```bash
npm audit fix --force
```

`--force`はメジャーバージョンの変更や互換性のない更新を行う可能性がある。

先に問題のあるパッケージと影響範囲を確認し、必要なものだけを更新する。

---

## 11. Awai Studioでの当面の判断

現在はバージョン更新を目的とした作業へ脱線しない。

次の順番で完成を優先する。

```text
ブログ
↓
レビュー
↓
GA4・GTM
↓
本番動作確認
↓
依存パッケージの更新確認
↓
共通雛形の検討
```

現在正常に動いている環境は維持し、明確な理由がない限り、制作途中でNode.js、Next.js、Reactの主要バージョンを変更しない。
