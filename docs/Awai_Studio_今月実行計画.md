   - 予約システムは、どちらからでも開始できる共通構成にする。

## **2. 上田プロジェクトから確認できた移植元**

### **2-1. GA4・GTM計測**

上田プロジェクトでは、次の流れを計測している。

| 利用者の行動 | GA4イベント | 主な用途 |
|---|---|---|
| LPを表示 | page_view | 訪問数の確認 |
| CTAをクリック | cta_click | どの導線が機能したか確認 |
| フォームを表示 | form_view | フォーム到達数の確認 |
| 送信を完了 | form_submit | 応募・問い合わせ完了数の確認 |

cta_clickにはcta_locationを付け、どの場所のCTAが押されたかをGA4で分析できるようにしている。

広告URLからは、少なくとも次の値を引き継ぐ設計になっている。

- utm_source
- utm_medium
- utm_campaign
- utm_content
- 最初にアクセスしたURL

### **2-2. 上田プロジェクトで実施した安全対策**

確認できた主な対策は次のとおり。

- ブラウザとAPIの両方で入力値を検証
- 氏名、メール、電話番号、問い合わせ内容、選択肢の許可値と最大長を検証
- 不正入力時は、DB保存・ファイル保存・メール送信を開始しない
- PDFの拡張子、MIMEタイプ、ファイル内容を確認
- ファイルを非公開Storageへ保存し、期限付きURLで閲覧
- SupabaseのRLSで外部からの直接取得・登録・更新・削除を制限
- 管理者をviewerとeditorに分け、更新権限を限定
- ハニーポット、入力時間判定、二重送信防止、接続元ごとの回数制限
- 接続元情報を直接保存せず、回数制限に必要な形へ変換
- 処理途中で失敗した場合、孤立したファイルを削除
- メール送信が失敗しても、受付済みデータを失わないよう処理を分離
- 秘密キーをサーバー側だけで使用し、GitHubへ登録しない
- 利用者の画面に内部エラーを表示しない
- サーバーログへ個人情報やエラー情報一式を出さない
- APIへの直接送信、HTML・JavaScript文字列、権限違反、障害時処理をテスト

## **3. Awai Studioへ移す内容**

### **3-1. ブログ（Awai Notes）**

短期間で確実に公開するため、現在のNext.jsサイト内に「Awai Notes」としてブログを追加する。

各記事は、**英語本文を先に掲載し、その後に同じ内容の日本語本文を追記する**。英語版と日本語版を別URLへ分けず、一つの記事の中で英語から日本語へ続く構成を基本とする。

- /blog：記事一覧
- /blog/[slug]：記事詳細
- タイトル、概要、公開日、更新日、カテゴリー、本文、OG画像
- 記事ごとのSEOタイトルと説明文
- OGP、Xカード、サイトマップ、RSS
- Instagram・Xへの共有導線
- 記事一覧のページ分割または追加読み込み

記事は一般的な京都観光情報の量産ではなく、これまで髙廣信之がジャックへ送ったメールと、茶室で実際に感じたことを元にする。

文章の基本構造は次のとおり。

1. 茶室で起きた具体的な出来事や、ジャックの言葉
2. 帰宅後も心に残ったこと
3. 世阿弥、書、禅、仏教の言葉などとの思いがけないつながり
4. ジャックへ考えを返すような語りかけ
5. 結論を言い切らず、読者にも考える余白を残す

過去の会話記録から、少なくとも次の原稿・主題を再利用できる。

- 「不二」と松風
- 「以心伝心」と世阿弥の「心より心に伝ふる花」
- ジャックの言葉と「初心を忘れべからず」
- 「書と茶のあいだで」――幻化空身即法身と四無量心
- ホストとゲスト、その空間に生まれる関係
- 61歳で茶・書・禅との出会いが始まったこと

これらは文化知識を教える記事ではなく、髙廣信之が文化の中を実際に歩き、感じ、ジャックへ語りかけた記録として編集する。

Awai Notesは、開発者がMarkdownファイルを直接追加するだけのブログにはしない。**許可された執筆者がログインし、Wordの簡易版のような画面で記事を作成・保存・公開できる、小型の記事管理システム**として実装する。

編集画面の基本方針は次のとおり。

- 一般の執筆者には、Markdown記号を意識しなくてよいリッチテキスト編集画面を標準表示する
- タイトル、見出し、本文、太字、箇条書き、リンク、写真の挿入に機能を絞る
- 記事本文は一段組みを基本とし、完成ページの表示に近い状態で編集できるようにする
- PC専用にはせず、スマートフォンでも本文入力、見出し変更、写真追加、下書き保存、プレビュー、公開まで完結できる編集画面にする
- スマートフォンではツールバーを必要最小限に絞り、画面からはみ出す操作は横スクロールまたは追加メニューへまとめる
- Markdownを扱える管理者には、リッチテキスト表示とMarkdown原文表示の切替機能を用意する
- 保存する本文の正本はMarkdown文字列とし、タイトル、URL、概要、公開状態、公開日、画像等の管理情報は別項目としてデータベースへ保存する
- 記事は「下書き」「公開」の状態を持ち、公開前に実際のページとしてプレビューできるようにする
- 英語本文と、その後に続く日本語本文を一つの記事として編集・公開できるようにする
- 写真は端末からアップロードできるようにし、本文には保存先URLをMarkdown画像として記録する

編集部品には、既製のReact用WYSIWYG Markdownエディターである@mdxeditor/editorを第一候補として採用する。この部品は、編集内容をMarkdown文字列として受け渡しでき、見出し、本文、リスト、リンク、画像、ツールバー、リッチテキストとMarkdown原文の切替を備えている。Next.js App Routerでは編集画面だけをブラウザ側で読み込む構成にする。

ただし、ライブラリ名にMDXと付いていても、一般執筆者の記事内でReact部品やJavaScriptを実行できるようにはしない。Awai Studioでは許可したMarkdown要素だけを保存・表示し、HTML、スクリプト、危険なURLを無条件に実行しない。

今月のCMS必須範囲は次のとおり。

1. 許可された執筆者のログイン
2. 記事一覧、新規作成、編集
3. Word風編集とMarkdown原文表示の切替
4. 画像アップロード
5. 下書き保存、プレビュー、公開・非公開
6. 公開ブログの一覧・記事詳細
7. 記事ごとのSEO情報、OGP、サイトマップ、RSS

共同校正、承認フロー、予約公開、詳細な更新履歴は、今月の完成後に追加する拡張範囲とする。

### **3-2. レビュー**

レビューは、誰でも自由に投稿できる掲示板にはしない。Awai Studioで予約し、実際に体験を終えた利用者へ専用リンクを送り、そのリンクから投稿してもらう。

今月の基本仕様は次のとおり。

- 予約の対応状態に「体験完了」を追加する
- 管理画面から、体験完了後の予約客へレビュー依頼メールを送る
- 利用者はログインせず、期限付きの専用リンクから投稿する
- 専用リンクは推測できない値とし、データベースにはそのまま保存せず照合用の値として保存する
- リンクの有効期限は送信から60日を基本とする
- 原則として一つの予約につき一件だけ投稿できるようにする
- 星評価、表示名または匿名、国・地域（任意）、感想本文を入力できるようにする
- サイトへの掲載同意を得る
- 公式Instagram・Xでの引用許可は、サイト掲載とは別の任意同意として得る
- **有料広告への使用許可は、今月の仕様に含めない**
- 投稿直後には自動公開せず、管理画面で内容を確認してから公開する
- 公開したレビューは、対応する体験のページだけに表示する
- 原文と翻訳文を分けて保存し、本人の文章を無断で書き換えない

レビュー写真の投稿、投稿者アカウント、複雑な自動配信は今月の必須範囲に含めない。最初は管理画面から手動で依頼を送ることで、安全性と実際の運用を確認する。

### **3-3. Awai Studio用の計測イベント**

上田プロジェクトと同じ骨格を保ちながら、ブログと予約導線を追加する。

| 行動 | イベント | 主な付加情報 |
|---|---|---|
| ページ表示 | page_view | ページURL、タイトル |
| ブログ記事表示 | article_view | 記事ID、カテゴリー、記事名 |
| CTAクリック | cta_click | cta_location、cta_label |
| Instagram・Xへの外部リンク | social_click | social_platform、link_location |
| 予約フォーム到達 | form_view | form_type |
| 予約送信完了 | form_submit | form_type、重複しない受付ID |
| レビュー投稿完了 | review_submit | 体験識別子。氏名、メール、本文は送らない |

form_submitをGA4の重要イベントとして扱い、Meta広告とX広告でも同じ完了地点をコンバージョンとして計測する。

### **3-4. Instagram・X広告との連動**

Instagram広告はMeta広告の仕組みで計測する。XはX Adsの仕組みで計測する。

- 全広告URLへ統一ルールのUTMを付与
- GA4でInstagramとXの流入・行動・送信完了を比較
- Meta Pixelでページ表示、記事閲覧、予約完了を計測
- X Pixelでサイト訪問と予約完了を計測
- GTMでGA4、Meta、Xのタグを一元管理
- 広告管理画面とGA4の数字が完全一致しないことを前提に、目的別に読み分ける
- 将来必要になれば、Meta Conversions APIやX Conversion APIのサーバー連携を追加

UTM命名例：

| 項目 | Instagram広告 | X広告 |
|---|---|---|
| utm_source | instagram | x |
| utm_medium | paid_social | paid_social |
| utm_campaign | キャンペーン共通名 | キャンペーン共通名 |
| utm_content | 広告クリエイティブ識別名 | 投稿・広告識別名 |

### **3-5. Awai Studioへ適用する安全対策**

上田プロジェクトの全対策を無条件に貼るのではなく、Awai Studioの機能に合わせて適用する。

必須対象：

- 予約フォームとAPIの共通入力検証
- 送信値の最大長、形式、許可値検証
- ハニーポット、最短入力時間、回数制限、二重送信防止
- 不正時にメール送信やDB保存を行わない制御
- 秘密情報のサーバー限定利用
- 利用者向けエラーと内部ログの分離
- セキュリティヘッダーと外部タグの許可範囲確認
- GA4、Meta、Xへ氏名、メール、電話番号等を送らない制御
- 記事作成・更新・公開APIをログイン済み執筆者だけに限定
- 記事本文で許可するMarkdown要素を限定し、HTML、スクリプト、危険なURLを無条件に表示しない
- 記事画像の種類、容量、保存先、公開範囲を検証
- レビュー依頼リンクを推測困難かつ期限付きにし、一つの予約からの重複投稿を防止
- レビュー本文、表示名、評価値、同意項目をAPI側でも検証
- 未確認のレビューを一般公開しないRLSと管理権限

該当機能がある場合のみ移植：

- Supabase RLS
- 管理者のviewer・editor権限
- 非公開Storageと期限付きURL
- PDFの三重確認
- 処理失敗時のファイル削除
